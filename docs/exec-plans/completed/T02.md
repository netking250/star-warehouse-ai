# T02 — Trusted Request / Task Context

## Objective

Create a typed, fail-closed request-to-Celery context that preserves tenant/user identity, trace/correlation linkage, conversation identity, deterministic idempotency identity, and sanitized payload guarantees across worker execution.

## In Scope

- Add one real `app/task_runtime` seam for task context, envelope validation, binding/cleanup, and current direct dispatch.
- Migrate confirmed request-sourced chat observability and memory task paths, plus other practical request task callers where compatibility risk is controlled.
- Separate execution metadata from task payload and reject missing tenant context without inferring a default.
- Remove raw chat questions from observability/task persistence and test the real dispatch-to-persistence seam.
- Preserve existing OpenTelemetry and structured logging systems.

## Non-goals

- No outbox, RabbitMQ migration, DLQ, consumer receipt, dedupe storage, retry redesign, memory dual-write repair, RLS, identity/RBAC, cookie sessions, Model Gateway, or Conversation Runtime rewrite.
- Current dispatch remains direct Celery publication; T03/T04 own reliable delivery.
