# T01 — Architecture Guardrails

## Objective

Establish a concise, executable architecture boundary for T02–T21 that prevents duplicate abstractions, cross-layer coupling, Big Bang rewrites, unreliable side-effect expansion, and unsupported enterprise claims.

## In Scope

- Create one Architecture Guardrail source of truth grounded in the current modular-monolith structure.
- Define dependency direction and the application/runtime, domain/ports, and infrastructure-adapter responsibilities.
- Record confirmed current debt and map it to T02–T17 without implementing it.
- Add only low-maintenance automation, prioritizing the Alembic single-head invariant.
- Route future Codex structural changes to the guardrail document through root `AGENTS.md`.
- Record T00 external acceptance and preserve its evidence.

## Non-goals

- Do not implement TaskContext, Outbox, RabbitMQ, memory repair, tenant/RLS, OIDC/RBAC, cookie auth, compliance, ConversationRuntime, ModelGateway, Enterprise Console, Kubernetes, or any T02–T21 capability.
- Do not create speculative deep-module directories, empty services, or empty interfaces.
- Do not move existing business files or broadly refactor current debt.

## Architecture Constraints

- Keep the modular monolith and independent API, worker, scheduler/Beat, and future outbox-relay deployment boundaries from ADR-004.
- Use progressive seam-first migration from ADR-005.
- Treat accepted decisions in `docs/engineering/DECISIONS.md` as frozen unless a later append-only ADR supersedes one.
- Preserve current T00 worktree changes and the green baseline.
