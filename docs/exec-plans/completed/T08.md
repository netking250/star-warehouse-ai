# T08 - Enterprise Identity

## Objective

Preserve local credentials while implementing generic OIDC authentication that resolves a durable
local identity by `issuer + subject`, fails closed during first linking, and returns the existing
application JWT without granting tenant membership or application authority from provider claims.

## Initial Findings

- Local password authentication and application JWT issuance are working compatibility paths.
- The current enterprise endpoint calls an OIDC UserInfo URL and resolves `User.email`; it has no
  durable issuer binding, cryptographic ID-token verification, state, nonce, PKCE, or concurrency
  protection.
- The current `User` is tenant-owned and requires a password hash, so T08 will link only existing
  local users and will not create OIDC-only accounts, tenant memberships, roles, or scopes.
- One configured generic issuer is sufficient; Keycloak is only the local demo provider.

## Behavior-First Plan

1. Add a tenant-owned external identity binding with database-enforced global uniqueness on
   `issuer + subject` and an additive migration after `a5b6c7d8e9f0`.
2. Add generic OIDC discovery, cached JWKS with unknown-`kid` refresh, strict ID-token validation,
   authorization-code exchange, state/nonce checks, and PKCE S256.
3. Add an identity application service that resolves known bindings first and permits first-link
   only when explicitly enabled, the configured provider is trusted, email is verified, and one
   active local user in the explicit tenant matches.
4. Keep OIDC claims out of application authorization and issue the existing local application JWT
   after identity resolution.
5. Add the optional Keycloak Compose profile and deterministic realm/client/demo-user import,
   focused documentation, targeted security/integration tests, and scoped quality gates only.
