# T00 — Reproducible Green Baseline

## Objective

Produce a reproducible, evidence-backed local engineering baseline using the repository's actual CI and development toolchain.

## In Scope

- Backend Python, dependency synchronization, Ruff, formatting, ty, pytest discovery, full CI test entry point, coverage, Alembic, and application import/startup.
- Frontend package-manager reproducibility, linting, unit tests, production build, and available type checks.
- Docker daemon and Compose availability, syntax/config validation, and runtime smoke when the daemon is available.
- Actual evidence in `docs/engineering/baselines/T00_BASELINE.md`.
- Baseline/tooling fixes only when evidence proves a reproducibility defect.

## Non-goals

- Do not implement work assigned to T01 onward, including tenant propagation, PII, outbox, RabbitMQ migration, RLS, identity, browser sessions, model gateway, or feature expansion.
- Do not conceal real product, external-dependency, test-infrastructure, or environment failures.
- Do not start T01 or self-assign `PASS`.

## Architecture Constraints

- Follow the accepted decisions in [`docs/engineering/DECISIONS.md`](../../engineering/DECISIONS.md).
- Preserve the existing Alembic history; do not reset, squash, or recreate databases to obtain a green result.
- Treat Demo and Production deployment profiles as distinct per ADR-015 and ADR-020.

## Implementation Plan

1. Read CI workflows and inspect installed toolchains, lockfiles, test discovery, migration metadata, Docker, and Compose.
2. Run CI-representative backend and frontend commands, recording actual outcomes.
3. Run Alembic and Compose checks; run Docker startup/smoke only when daemon availability permits.
4. Diagnose and fix only reproducibility/tooling defects that are within T00 scope; rerun affected commands.
5. Write `T00_BASELINE.md`, append the execution ledger, update current state and roadmap, and hand off as `AWAITING_ACCEPTANCE` or a truthfully classified blocked/evidence state.

## Acceptance Criteria

- Evidence records Python, Node/npm, Docker/Compose, backend, frontend, Alembic, Compose, startup, known failures, and environment blockers.
- Ruff, format check, ty, pytest, frontend tests/build, and the CI-required test entry point are actually attempted.
- Alembic single-head and executable upgrade evidence are captured when a database is available.
- `git diff --check` and state consistency checks pass.
- T00 does not self-assign `PASS` and T01 remains unstarted.

## Verification Commands

- CI workflows and local tool versions.
- `uv sync --frozen`, `uv run ruff check app tests`, `uv run ruff format --check app tests`, `uv run ty check --error-on-warning app tests`, and `uv run pytest --cov=app --cov-fail-under=75`.
- Frontend package install, `npm run lint`, `npm run test`, and `npm run build`.
- `alembic heads`, migration upgrade where database access exists.
- `docker version`, `docker compose version`, and Compose config validation.

## Current Findings

- Ruff, backend format check, ty, application import, identity validation, frontend lint/unit tests/build, Alembic single-head/history, and both Compose config validations passed.
- The authorized repository formatter normalized the 95 previously failing frontend files; format check, lint, unit tests, and build now pass.
- Docker Engine is available. The existing Compose stack built with a 4.37 MB context, all project services became healthy on temporary non-conflicting host ports, and `/health` returned HTTP 200 with database, Redis, and Qdrant connected.
- Root cause of the migration failure was invalid lineage: `3a9f8e7b2c1d` altered `message_feedbacks` before `053eaa2f0a66` created it, while downstream `c61a28a53622` duplicated the same feedback columns and `experiment_metrics` DDL.
- The repair preserves every revision ID, places `3a9f8e7b2c1d` directly after the table-creating revision, and removes only duplicate operations from `c61a28a53622`. Existing databases already at head run no migration; databases at the repaired boundary receive additive changes without data deletion.
- A fresh empty PostgreSQL database upgraded to the single head `b7c6d5e4f3a2`; `message_feedbacks` has all expected columns and indexes.
- The formal backend gate passed: 1533 tests passed, 0 failed, 0 skipped, with 79.43% coverage. Ruff, format check, and ty also passed.
