## Safety contract

- Every load/failure/restore command must require an explicit target and reject `prod` and
  `production`. Destructive modes additionally require an explicit confirmation flag.
- Default load is a small smoke profile. Baseline, async burst, AI mock, and short soak require an
  explicit profile; heavier bounded profiles require opt-in.
- The runtime target will use a unique disposable k3d/k3s cluster/namespace, database, Redis
  namespace/instance, RabbitMQ vhost/instance, Qdrant collection/instance, and local artifact
  directory. No cloud discovery or deletion is permitted.
- Before destructive execution record `production touched = NO`; after execution record exact
  resource cleanup. Stop immediately for corruption, duplicate durable effect, cross-tenant access,
  false terminal success, or unrecoverable Outbox evidence.
