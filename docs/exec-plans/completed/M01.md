## Initial Inventory Findings

- The repository has one application Compose file (`docker-compose.yaml`) and
  one independently invoked monitoring Compose file
  (`docker-compose.monitoring.yml`).
- Both Compose files use fixed `container_name` values even though scripts and CI
  primarily use service-oriented `docker compose` commands.
- `Dockerfile.save` is an unreferenced, truncated historical copy; the canonical
  root `Dockerfile` supersedes it.
- RabbitMQ is the runtime Celery broker, but CI and environment documentation
  still contain Redis broker URLs.
- The root `.env.example` documents RabbitMQ, while Compose currently warns when
  `RABBITMQ_PASSWORD` is absent because no development default is defined.
- Local generated artifacts are ignored and untracked. `uploads/` is local
  runtime state but is not currently ignored.
- `start.sh` is a stale duplicate path that omits RabbitMQ, the scheduler, and
  the outbox relay. `celery_worker.py` is copied into images but never invoked.
- Current test startup protects PostgreSQL names and uses run-scoped Qdrant
  fixture collections, but Redis still defaults to DB 0 and generic CI still
  configures a Redis Celery broker.
- `app/core/config.py` repeats Redis settings in one class; the effective second
  definitions are the ones used by the Redis client, while two legacy circuit
  names have no consumers.
