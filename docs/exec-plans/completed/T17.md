## Objective

Make the existing OpenTelemetry, Prometheus/Mimir, Grafana, Loki, Tempo, Alertmanager, and local
Compose observability path coherent across API requests, the trusted async envelope, outbox
relay, RabbitMQ/Celery workers, conversation runtime, and the T13/T14 model policy. Keep telemetry
safe, bounded, actionable, and non-blocking.

## T17 API Trace Fix

Completed: 2026-09-16

Status: `IN_PROGRESS`

Execution stage: `VERIFY_PENDING`

Primary root cause: `API_TELEMETRY_INITIALIZATION_ORDER`

- The failure reproduced for `5/5` inbound sampled requests: normalized HTTP metrics and JSON
  access logs existed, all five trace IDs returned Tempo `404`, and the responses omitted the
  repository's existing `X-Trace-ID`. Scheduler traces were present through the same Collector.
- Runtime/source inspection showed OpenTelemetry FastAPI 0.62b0 replaces
  `build_middleware_stack`, while Starlette 0.48.0 builds and caches that stack before entering
  lifespan. Calling `instrument_fastapi(app)` from lifespan therefore changed a builder that the
  live request path no longer used.
- The smallest fix moves the existing provider setup and FastAPI instrumentation to the end of app
  assembly, before the first ASGI call. It does not change sampling, processor bounds, OTLP gRPC
  endpoint, Collector configuration, service naming, routes, or business behavior.
- A second focused correlation defect was proven independently: root logger filters do not run for
  propagated child records. The existing `CorrelationIdFilter` is now also attached to the shared
  handler, allowing application JSON logs to contain `correlation_id`, `trace_id`, and `span_id`
  together without logging request bodies or trace headers.
- Regression tests were red before each correction and green afterward. The final compact set
  passed `17` tests covering API server-span recording, existing response headers, structured-log
  correlation/redaction, normalized HTTP labels, W3C TaskEnvelope preservation, and T02 context
  binding/cleanup.
- Real-stack proof passed: `5/5` requests returned matching `X-Trace-ID` values and were queryable
  in Tempo under bounded service identity `star-warehouse-ai-api`. A synthetic tenant-resolution
  failure produced the normalized `/api/v1/login` metric and a Loki JSON event with correlation ID
  `t17-fix-correlation-proof-205`, trace ID `17000000000000000000000000000205`, and a valid span ID;
  the same trace was present in Tempo. Scheduler traces remained queryable.
- Exact synthetic password and username searches returned zero Loki matches. Ruff, format, ty,
  disposable Compose validation, route inventory (`136` classified, `0` unclassified), and the
  single Alembic head `e9f0a1b2c3d4` passed. No migration, new route, Collector change, T18 work,
  or T02/T03/T04 context/transaction change was made. All disposable resources were removed.
