## Design Decisions

- `apiFetch` remains the only generic browser HTTP entry point. It always sends
  `credentials: "include"`, attaches the existing CSRF proof only to unsafe methods, and never
  creates a browser Bearer header.
- HTTP failures, network failures, timeouts, and caller aborts use one bounded `TransportError`
  model. Error details are sanitized and bounded before reaching UI code.
- Safe reads may use at most two transport attempts with bounded delay. Mutations do not retry by
  default; an explicit idempotency key is required before a caller can opt into a mutation retry.
  TanStack Query owns no additional retries, avoiding multiplicative attempts.
- The backend owns correlation-ID generation. The client forwards only an optional safe caller ID
  and captures response correlation/request IDs; it does not put tenant, user, email, or prompt
  data in headers.
- SSE parsing is protocol-only. T12 runtime events identify `TURN_ACCEPTED`, run identity, durable
  terminal status, and logical cancellation; duplicate terminal events and late deltas are ignored.
- Browser WebSocket authentication remains cookie/origin based. Reconnect is bounded, jittered,
  and disabled for authentication/authorization failure, normal close, logout, and disabled auth.
