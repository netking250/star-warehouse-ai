# T03 — Transactional Outbox

## Objective

Persist critical business state and its required sanitized task envelope in the same PostgreSQL transaction, then relay pending events to the existing Celery transport with explicit at-least-once semantics.

## Delivery Semantics

- Business data plus outbox enqueue: atomic in the caller-owned database transaction.
- Outbox to current Celery transport: at-least-once.
- Duplicate publication remains possible if publish succeeds and marking the event published fails.
- Exactly-once is not claimed; the event retains its idempotency key for T04 consumer deduplication.
