# T14 — AI Failure Policy

## Objective

Add one provider-neutral failure-policy seam around the accepted T13 ModelGateway. The policy owns
finite retry budgets, bounded backoff/jitter, ordered candidate fallback, provider circuit state,
safe terminal degradation, and cancellation-safe streaming behavior. T13 adapters and gateway
remain single-attempt/single-candidate components; T12 durable runtime semantics remain unchanged.

## Scope and invariants

- `ProviderAdapter` performs one provider attempt and preserves cancellation.
- `ModelGateway` resolves candidates and invokes one explicit candidate without retry/fallback.
- `ModelFailurePolicy`/`ResilientModelExecutor` is the only model retry/fallback/circuit owner.
- Retry and fallback consume only normalized `ModelErrorCategory` values.
- TIMEOUT, CONNECTION, RATE_LIMIT, and PROVIDER_UNAVAILABLE are transient by default; security,
  validation, capability, cancellation, tool, and safety failures are not retried or bypassed.
- Streaming can retry/fallback before a visible text/tool delta, never after one.
- Circuit keys contain only a provider/model digest; Redis system state coordinates instances and
  half-open probes. Redis outages fail open for the breaker only while local attempt/deadline
  limits remain enforced.
- Default degradation is `FAIL`; an explicitly configured safe static response cannot satisfy
  tool or structured-output requests.
- No route, schema migration, dependency upgrade, T15 work, or public-provider test is in scope.

## Default error policy

| Normalized category | Retry | Fallback | Circuit |
| --- | --- | --- | --- |
| `TIMEOUT`, `CONNECTION`, `RATE_LIMIT`, `PROVIDER_UNAVAILABLE` | Yes, bounded | Yes, after candidate budget | Yes |
| `AUTHENTICATION`, `BAD_REQUEST`, `UNSUPPORTED_CAPABILITY`, `INVALID_RESPONSE`, `UNKNOWN` | No | No | No |

`INVALID_RESPONSE` can be explicitly enabled for retry/fallback through the trusted server-side
setting `MODEL_FAILURE_RETRY_INVALID_RESPONSE`; it never trips the operational circuit. Cancellation,
safety, authorization, and downstream tool failures remain outside this model policy.

## Implementation

- `app/model_gateway/failure_policy.py` contains validated policy configuration, the async executor,
  in-memory test store, and Redis-backed circuit store.
- `GatewayChatModel` delegates async invoke/stream calls to the policy while retaining the existing
  LangChain compatibility surface.
- Factory-created clients use the trusted `Settings.MODEL_FAILURE_*` bounds and shared Redis store;
  direct test clients use an injectable in-memory store.
- Low-cardinality model attempt, retry, fallback, circuit-transition, and degradation metrics are
  recorded through `app.observability.metrics`.
