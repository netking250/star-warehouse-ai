## Implementation closeout

### Canonical bootstrap and startup

- `scripts/bootstrap_local_data.py` is the only canonical local/UAT data entry point, backed by the
  deep `app.bootstrap.local_data` module. It refuses production, requires
  `LOCAL_BOOTSTRAP_ENABLED=true`, reads identities/passwords only through typed settings, never logs
  passwords, uses stable identifiers, and reconciles rather than appends.
- `scripts/seed_data.py`, `scripts/initialize_vector_data.py`, and
  `scripts/seed_product_catalog.py` are compatibility wrappers that delegate to the canonical
  entry point. New documentation and automation use only the canonical name.
- `start_docker.sh` explicitly passes `--project-name`, health-checks infrastructure, applies and
  verifies one Alembic head, provisions and login-verifies runtime/maintenance database roles,
  bootstraps data and derived indexes, starts API/tenant worker/maintenance worker/scheduler/outbox,
  waits for health, runs `scripts.verify_local_stack`, and prints working URLs.
- The first isolated attempt exposed two startup integration defects before business data was
  created: Compose project-name propagation and shell-to-Compose JSON quoting for CORS. Explicit
  `--project-name` use and an internally generated port-aware CORS JSON default fixed both. The
  exact failed disposable project was inventoried and removed; the developer's default project and
  volumes were never deleted.
- Alembic remains schema-authoritative. New head `f0a1b2c3d4e5` makes the knowledge sync timestamp
  timezone-aware; no prior migration was rewritten.
