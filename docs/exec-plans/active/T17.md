# T17 - Production Observability Hardening

Status: `IN_PROGRESS`

Execution stage: `VERIFY_PENDING`

Branch: `feat/t14-t21-enterprise-hardening`

## Objective

Make the existing OpenTelemetry, Prometheus/Mimir, Grafana, Loki, Tempo, Alertmanager, and local
Compose observability path coherent across API requests, the trusted async envelope, outbox
relay, RabbitMQ/Celery workers, conversation runtime, and the T13/T14 model policy. Keep telemetry
safe, bounded, actionable, and non-blocking.

## Invariants

- T02 `TaskContext`/`TaskEnvelope` remains the only trusted request-to-task context.
- Outbox at-least-once publication, RabbitMQ routing, Celery ACK/retry behavior, and T12 terminal
  uniqueness remain unchanged.
- Metric labels are route templates or bounded configured categories only; no tenant, user,
  request, correlation, conversation, run, prompt, URL, exception-message, or payload labels.
- Exporter failure is best effort and bounded; it cannot fail a business request.
- No database migration or public application-facing telemetry control API is added.
