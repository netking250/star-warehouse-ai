## Information Architecture

- `/` — Overview.
- `/operations` — operations status, review queue, and conversation metadata where the current
  operator has the corresponding capabilities.
- `/ai` — existing agent configuration/evaluation surface under the shared console shell.
- `/security` — current-tenant membership and effective capabilities.
- `/compliance` — sensitive-export approval metadata and bounded retention operations.
- Existing `/knowledge`, `/feedback`, and `/metrics` routes remain stable and are attached to the
  same single shell; no duplicate admin navigation tree is introduced.

## Implementation Constraints

- Use current `/me` scopes for UX visibility only; never use username, email, JWT role claims, or
  `is_admin` as authority.
- Keep sensitive values out of the UI: passwords, tokens, session secrets, API keys, provider
  credentials, and raw sensitive export content are never rendered.
- Use server pagination and existing query parameters only. No unbounded client fetches or
  arbitrary polling is introduced; operational refresh is manual/bounded.
- Use one confirmation dialog pattern for role/status changes, approval decisions, retention
  execution, and existing high-impact actions touched by T16.
- On 401, clear the browser session and privileged cache. On 403, preserve authentication, remove
  stale privileged cache, and reconcile current `/me` capabilities.
- No backend route, schema, migration, provider secret storage, T17 observability work, or
  deployment control is in scope.
